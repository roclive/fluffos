# 知识库应覆盖的维度（"还有哪些维度的信息"）

你点名了：地图、精/精力/气/血、任务、功法、常识。下面是一份**完整的维度清单**，
按"对 agent 智能性的贡献"排序。⭐ = 强烈建议纳入。

## A. 空间与导航 ⭐
- **房间图 / 路线**（map.json）——已覆盖。
- **区域元数据**：城镇/野外/危险等级/是否 PK 区/是否新手保护区。影响 agent 敢不敢去。
- **关键地标**：钱庄、药店、武器店、客栈、镖局、传送点、各门派山门位置。
- **跨区交通**：船、车、镖队、城门连接——往往是地图断链处，单独建表。

## B. 角色状态语义 ⭐
- 精/气/精力/内力/血 的含义与阈值——已覆盖（attributes.md）。
- **状态机文案表**：把"低血/中毒/受内伤/昏迷/busy/中了xx功"等游戏文案 → 标准状态枚举，
  让 parseFluffosText 从启发式升级为查表，这是提升感知准确率最直接的一招。
- **buff/debuff**：中毒、受伤减益、增益持续效果。

## C. 战斗模型 ⭐
- **武功 / 功法**（skills.json）——已覆盖分类。
- **招式消耗表**：每招耗多少内力/精力，供 agent 算"还能打几招"。
- **克制关系 / 命中-闪避**：兵器 vs 徒手、轻功对闪避的影响。
- **战斗动作集**：kill/fight、运功、疗伤、逃跑(flee)、防御——动态生成 available_actions。

## D. 经济与物品 ⭐
- **物品表**：武器/防具/药品/任务物品，含属性、可否装备、价值。
- **货币体系**：金/银/铜的换算，钱庄存取。
- **商店**：哪里卖什么、买卖价。agent 补给与变现要用。

## E. 任务系统 ⭐
- **任务表**（quests.json）：触发条件、前置、步骤、奖励、相关 NPC 与房间。
- **任务状态跟踪**：进行中/已完成/可接，配合事件流更新。

## F. NPC 与社交
- **NPC 表**：身份、所在房间、态度（友善/中立/敌对）、可对话/可拜师/可交任务。
- **门派师傅**：谁能教什么武功、拜师条件。
- **对话/触发词**：哪些 NPC 对特定关键词有反应（接任务的钩子）。

## G. 门派与身份
- **门派表**：正邪倾向、专属武功树、入门流程、声望。
- **角色身份/等级称号**：影响可去的地方与 NPC 反应。

## H. 时间与节律
- **游戏内时间 / tick**：商店开关、NPC 刷新、昼夜。
- **冷却(cooldown)**：gateway 已留 `cooldowns` 字段但没用起来——值得填，避免刷屏式连发。

## I. 规则与"常识" ⭐
- **生存常识**：低血先撤、内伤要养不要硬扛、没钱先变现。
- **操作常识**：命令语法（go/kill/get/buy/learn/拜师 的确切写法，按服务器）。
- **危险常识**：哪些 NPC/区域会秒杀新手、哪些行为触发全城追杀。
- **礼仪/反作弊**：刷屏、外挂检测——避免 agent 被服务器踢。

## J. 运行时记忆（让 agent 跨会话变聪明）⭐
- **去过的房间 / 已知 NPC / 关键事件摘要**：补 gateway 当前缺失的长期记忆，
  避免 COMPACT 把重要信息丢光。建议单独 `memory.json`，与静态知识库分离。

---

## 落地优先级建议
1. **状态机文案表（B）** + **战斗动作集（C）**：立刻提升感知与行动准确率，改动小、收益大。
2. **房间图（A）**：解决你点名的扬州→少林导航。
3. **任务表 + NPC 表（E/F）**：让 agent 有"目标"而非乱逛。
4. **运行时记忆（J）**：让它越玩越懂这台服务器。
